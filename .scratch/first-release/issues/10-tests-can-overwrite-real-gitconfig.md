# The test suite can overwrite your real `~/.gitconfig` on git 2.31

Category: bug
Status: needs-triage

## Problem

`setup` in `test/run.sh` isolates git config with `GIT_CONFIG_GLOBAL="$T/gitconfig"`, then runs three `git config --global` lines (user.name, user.email, init.defaultBranch). `GIT_CONFIG_GLOBAL` was added in git 2.32, but the README's stated minimum is 2.31. On git 2.31 the variable is ignored, so running the tests writes `test` / `test@example.com` / `main` into the developer's real `~/.gitconfig`.

## Notes

Either raise the stated minimum to 2.32, or isolate by also setting `HOME="$T"` in `setup`, which works on every git version. Setting `HOME` is the safer choice, because a test suite should never be able to touch real config.
