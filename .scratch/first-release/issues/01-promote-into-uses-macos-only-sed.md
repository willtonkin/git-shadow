# `promote --into` uses macOS-only `sed -i ''`

Category: bug
Status: needs-triage

## Problem

`cmd_promote` rewrites the `.branch` marker with `sed -i '' …` (`bin/shadow`, the `--into` branch). GNU sed reads `''` as the script and fails, so `shadow promote <branch> --into <new>` breaks on Linux after it has already moved the area. That leaves the folder renamed but `.branch` still naming the old branch.

The rest of the script sticks to portable bash and git, and the test suite has only run on macOS.

## Notes

Rewrite `.branch` without in-place sed (for example, write a fresh file with `printf`), and do it before the `mv`, so a failure leaves nothing half-done.
