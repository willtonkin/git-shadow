# `init` in a repo with no remote creates `$SHADOW_HOME/.git`, which can't be found again

Category: bug
Status: needs-triage

## Problem

A repo with no remote is matched by `path:/abs/path/to/.git`. `cmd_init` uses `basename "$key"` for the default name, which gives `.git`, so it creates `$SHADOW_HOME/.git/`. `find_shadow` globs `"$SHADOW_HOME"/*/.shadow`, which skips dot-directories, so the shadow repo is never found:

- `shadow sync` says there is no shadow repo and to run `shadow init`;
- `shadow init` again says `$SHADOW_HOME/.git already exists`.

Passing an explicit name (`shadow init my-app`) avoids it.

## Notes

For `path:` keys, default to the basename of the checkout (the parent of `.git`). Separately, `init` should probably reject any name starting with `.`.
