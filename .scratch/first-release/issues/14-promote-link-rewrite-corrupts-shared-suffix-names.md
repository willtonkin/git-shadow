# Promote's link rewriting corrupts file names that share an ending

Category: bug
Status: needs-triage

## Problem

When `numbered` renames files, `cmd_promote` rewrites references with `perl -pi -e 's/\Q$ENV{O}\E/$ENV{N}/g'`. This matches the old basename anywhere in the text, with no boundary check. Promoting `tokens.md` and `session-tokens.md` together turned a reference to `session-tokens.md` into `0001-session-0002-tokens.md`.

## Notes

Anchor the match so the name can't be preceded by a filename character, for example `(?<![\w.-])\Q$ENV{O}\E`. Then add a test with two names that share an ending. This is separate from 07, which is about how *far* the rewriting reaches.
