# Autocommit can label other checkouts' changes as its own

Category: bug
Status: needs-triage

## Problem

`hook-end` runs `git add -A` on the whole shadow repo, then commits as `chore: sync from <this branch> (<this checkout>)`. If several sessions run in different worktrees at once, whichever ends first commits everyone's changes under its own branch name. The data is safe, but the history is wrong about where changes came from.

## Notes

Changes under `branches/<slug>/` can be attributed to the right branch. For shared paths, the honest options are a neutral message, or one commit per changed path with no branch named.
