# `promote --into` fails after the usual branch rename

Category: bug
Status: needs-triage

## Problem

The normal rename workflow is `git branch -m old new`, then start a session. `hook-start` syncs, and `sync_branch_link` creates an empty area `branches/new/` (with only `.branch` and empty folders). `shadow promote old --into new` then treats any existing destination as a clash and dies with "new already has per-branch files; merge them by hand", even though the area has no files.

## Notes

Treat a destination with `branch_file_count` = 0 as free: remove it, then move. Only stop when the destination has real files. Fix this together with 01, which touches the same few lines.
