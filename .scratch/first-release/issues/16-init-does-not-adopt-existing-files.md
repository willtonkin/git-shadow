# `init` doesn't adopt existing files, despite the README's advice

Category: bug
Status: needs-triage

## Problem

The README says untracked files at a linked path are moved into the shadow repo, and to "Run `init` in the checkout where you already have them." But the manifest `init` writes has no `link` lines, so the `sync_checkout` that `init` runs has nothing to adopt. Adoption actually happens on the first `sync` after you add link lines. With `sync --all`, whichever worktree is synced first gets its copy adopted, which might not be the checkout you ran `init` in.

Found by reading the code; not run.

## Notes

Either fix the README (run `shadow sync` in the checkout that has the files *before* `sync --all`), or let `init` take paths (`shadow init --link AGENTS.md --link .scratch/`) so adoption really happens at init.
